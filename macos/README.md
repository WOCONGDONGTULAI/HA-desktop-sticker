# macOS 贴纸

无边框、圆角的桌面小窗，里面是 Home Assistant 仪表盘。不进 Dock、不进 `Command+Tab`，只在菜单栏留一个图标。

## 装（两种方式，挑一个）

### A. 直接下载现成的 app

去 [Releases](https://github.com/WOCONGDONGTULAI/HA-desktop-sticker/releases) 下载
`HASticker.app.zip`，解压后把 `HASticker.app` 拖进「应用程序」文件夹，双击运行。

首次打开如果提示「无法打开，因为它来自身份不明的开发者」：右键 app → 「打开」→ 确认
（自己编译的 app 没有苹果开发者签名，这是正常现象，只第一次要这样）。

### B. 自己编译

```bash
cd macos
chmod +x make-app.sh
./make-app.sh
```

产出 `macos/HASticker.app`。脚本优先用 SwiftPM；机器上 SwiftPM 不完整时会自动退回 `swiftc` 直接编译。

> 第一次运行可能被 Gatekeeper 拦：右键 app → 「打开」→ 确认。脚本已经帮你清过 quarantine 标记。

要求 macOS 12+（Apple Silicon 与 Intel 通用，现成 app 是 arm64 版；Intel 机器用方式 B 自己编译）。
编译需要 Xcode 命令行工具（`xcode-select --install`）。

## 用

首次运行自动弹设置框，两条路选一条：

### A. 原生面板（推荐，默认）

不走网页，直接调 HA 的 REST + WebSocket，界面自己画：干净、秒开、没有 HA 顶栏和菜单、
**完全没有滚动条**。

填两个东西：
1. **Home Assistant 地址**：填到端口就行，比如 `http://192.168.5.18:8123`
2. **长期访问令牌**：HA 网页左下角点你的用户名 → **安全** → 页面底部「长期访问令牌」
   → 创建令牌 → 复制，粘进设置里

令牌只存在本机 `~/Library/Application Support/HASticker/settings.json`，不会外传。

**改贴纸上放什么、叫什么、用什么图标**：菜单栏图标 →「**编辑贴纸内容…**」（或快捷键 `E`）。
打开后左边是贴纸现在的样子（从上到下就是贴纸上的顺序），右边是 HA 里全部实体：

- 删掉一个：点该行的 `✕`
- 加一个（开关、灯、传感器、自动化都行）：在下面「添加设备 / 传感器」里搜名字或 `entity_id`，点「添加」
- 调顺序：`↑` `↓`
- 改标题：直接点名字改
- **换图标**：点最左边的图标方块，从 macOS 自带图标里挑一个（也可以直接填 SF Symbol 名字）
- **用自己的图片当图标**：点图标方块旁边的「🖼」按钮 → 分别上传「开着的样子」和「关着的样子」
  两张图（PNG / JPG 都行，会自动缩到 256px 存到本机 `…/HASticker/icons/`）。
  关的状态不传就用开着那张；想撤掉点「清除图片」回到苹果图标
- 传感器也能加：点不动，但会把数值显示在磁贴上（室温、湿度、电量这类）

保存后贴纸立刻刷新，不用重启。这些设置存在 `settings.json` 的 `entities` / `names` / `icons` 里
（`entities` 就是逗号分隔的 entity_id，想手改也认得）。列表清空 = 回到自动模式：
自动显示所有 开关 / 灯 / 风扇 / 空调，最多 12 个，按名字排序。

图标不是 HA 的 mdi 图标——macOS 上没法直接用，所以是按设备名字和类型猜一个最像的 SF Symbol，
猜得不准就在编辑器里换掉。

### B. 网页

填仪表盘地址，比如：
```
http://homeassistant.local:8123/ha-sticker?kiosk
```
第一次会跳 HA 登录页，登录一次之后永久自动登录。

菜单 →「内容来源」可以随时在两种之间切换。

想开机自启：系统设置 → 通用 → 登录项 → 把 `HASticker.app` 加进去。

## 操作

### 两种状态

| 状态 | 怎么进 | 能干什么 |
| --- | --- | --- |
| **调整模式**（默认） | 菜单里「锁定」**不勾选** | 贴纸任意位置按住左键就能拖；拖边缘缩放；顶部自动出现拖动条，四周有一圈细描边 |
| **锁定** | 菜单里勾选「锁定」 | 位置大小全部固定，拖不动也缩放不了，只能点里面的开关。拖动条和描边全部隐藏 |

调好位置 → 勾选「锁定」，就再也不会被误拖跑了。想重新调整就取消勾选。

| 操作 | 怎么弄 |
| --- | --- |
| 移动 | 调整模式下，在贴纸任意位置按住左键拖（或拖顶部那条横杠） |
| 点开关 | 直接点，不用按修饰键。位移小于 4pt 才算点击，不会误触 |
| 缩放 | 调整模式下拖贴纸边缘 |
| 菜单 | **点菜单栏右上角的贴纸图标**（在贴纸上右键不弹菜单） |
| 显示 / 隐藏 | 菜单里第一项 |

菜单里能改：贴法（桌面层 / 置顶 / 普通）、**外观（跟随系统 / 始终浅色 / 始终深色）**、
透明度、锁定位置、**开机自动启动**、**编辑贴纸内容（哪些磁贴 / 名字 / 图标）**、
重新加载、刷新显示、清除登录状态、退出。

## 开机自动启动

菜单栏图标 → **「开机自动启动」**，勾上就行，下次登录贴纸会自己出现在桌面上。

实现是往 `~/Library/LaunchAgents/com.congdongtulai.HASticker.plist` 放一份 launchd 配置
（macOS 13 才有 `SMAppService`，这套 12 也能用）。**取消勾选**就是把那份文件删掉。

注意两点：
- 因为它走的是 launchd，**不会出现在「系统设置 → 通用 → 登录项」里**，开关只在这个菜单里；
- app 换了位置（比如从「下载」挪到「应用程序」）不用管，启动时会自动更新里面记的路径。

## 深浅色

默认是「跟随系统」：系统切成深色，贴纸和里面的 HA 仪表盘一起变深色，不用重启。
想固定某一种就在菜单 → 外观 里选「始终浅色 / 始终深色」。

实现上是两层保险：
1. 给窗口和 `WKWebView` 设 `NSAppearance`，网页的 `prefers-color-scheme` 就跟着变，
   HA 前端主题设为「默认（跟随系统）」时会自动切；
2. 另外注入一段脚本，直接给 HA 的 `home-assistant` 元素发 `settheme` 事件强制切主题，
   这样即使前端没在跟随系统也能切过去。

设置存在 `~/Library/Application Support/HASticker/settings.json`，删掉这个文件就恢复默认。

## 滚动条

贴纸里的网页滚动条默认是**隐藏的**（滚动时短暂浮出，松手就消失），不占那 15px 宽度。

实现上试过四条路，只有最后一条对所有情况都有效：

| 办法 | 结果 |
| --- | --- |
| 文档级 CSS `::-webkit-scrollbar{width:0}` | 只对主文档有效，**穿不进 shadow DOM** |
| 把 CSS 塞进 shadow root | 样式在，但滚动条照画（HA 是 Lit 写的，页面几乎全是 shadow DOM） |
| `WKWebView` 私有开关 `_setAlwaysShowsVerticalScroller:` | 无效 |
| **app 域里设 `AppleShowScrollBars = WhenScrolling`** | ✅ 全部生效，0px |

关键点是：系统设置 → 外观 →「显示滚动条」如果是**「始终」**，WebKit 会画 15px 常驻滚动条。
`NSUserDefaults` 的查找顺序是 app 域 → 全局域，所以把 `AppleShowScrollBars` 写进
**本 app 自己的域**就能只覆盖这一个 app，不动系统全局设置：

```swift
UserDefaults.standard.set("WhenScrolling", forKey: "AppleShowScrollBars")  // 必须在建 WKWebView 之前
```

除此之外还注入了文档级 CSS（主文档的滚动条彻底消失）+ 劫持 `attachShadow` 往每个
shadow root 里塞样式（能盖住的就盖住）。

> 想恢复常驻滚动条：`defaults write com.congdongtulai.HASticker AppleShowScrollBars Always`
> 然后重启贴纸。

## 贴法说明

| 模式 | 表现 |
| --- | --- |
| **desktop**（默认） | 窗口 level = **桌面图标层 +1**，即压在图标上面、普通窗口下面：切桌面空间都在，开其他程序时被正常遮挡 |
| **top** | 永远浮在别人上面，随手能点 |
| **normal** | 普通小窗口 |

> ⚠️ **桌面层为什么必须站在图标层之上**
> Finder 的桌面图标是一块**铺满全屏的透明窗口**（level `-2147483603`）。macOS 的点击命中
> 只看「光标处最上层的那个窗口」，不看它透明与否。所以窗口只放到 `desktopWindow + 1`
> （`-2147483622`）会被它整块盖住 —— 表现就是：贴纸看得见，但**点哪里都没反应、
> 拖也拖不动，桌面图标还会从贴纸上透出来**。
> 现在用 `CGWindowLevelForKey(.desktopIconWindow) + 1`，既压住图标，又远低于普通窗口(0)。

> macOS 没有 Windows 那种「挂到 Explorer 桌面窗口上」的办法，桌面层是靠窗口 level 模拟的，
> 效果接近：跟着桌面显示、不抢焦点、不在 `Cmd+Tab` 里。

## 打字 / 粘贴

贴纸里的 HA 登录框可以直接打字，`Cmd+V / Cmd+C / Cmd+X / Cmd+A` 都能用。

实现上走了三层（Nib-less app 默认一个都不通）：

1. 程序里手工建了主菜单的「编辑」子菜单（`Cmd+V` 等靠菜单项走响应链）；
2. 窗口层面拦 `performKeyEquivalent`，把 `Cmd+V/C/X/A` 直接转发给第一响应者；
3. 万一上面都不通，菜单栏菜单里有「粘贴到页面」，读剪贴板后直接写进网页里聚焦的输入框。

> 贴纸窗口**没有**用 `.nonactivatingPanel`：带了它点击不会激活 app，窗口拿不到键盘焦点，
> 登录框里既打不了字也粘不了东西。代价是点贴纸会切换一下当前应用，这是能输入的必要代价。

## 常见问题

**贴纸看着正常，但点开关没反应 / 拖不动**
八成是窗口被桌面图标层压住了。判断特征：**桌面图标会透过贴纸显示**，而且贴纸里
**任何地方都点不到**（连登录框都点不进去）。这是 v8 及更早版本的问题，v9 已修
（窗口 level 从「桌面层 +1」抬到「桌面图标层 +1」）。升级到最新版即可。

**白屏 / 打不开**
- 地址填对没。菜单栏图标 → 设置，改完自动重载。
- 内网 `http://` 已被 `Info.plist` 的 `NSAllowsArbitraryLoads` 放开。
- macOS 15 起会弹「本地网络」权限，一定选**允许**，否则连不上 `homeassistant.local`。

**菜单栏没图标**
app 是 `LSUIElement=1`（不占 Dock），只有菜单栏入口。如果图标被别的 app 挤掉了，从右边往左找。

**改代码**
```bash
swift build          # 编译
./make-app.sh        # 编译 + 打包
```
想用 Xcode 打开：`open Package.swift`（Xcode 12+ 支持 SPM 工程）。

## 磁贴排布

磁贴会自动按高度决定列数：2 个就是 1 列，5～6 个 2 列，7 个以上自动加到 3 列，
最多 4 列——保证所有磁贴都塞得进窗口，不会被底部切掉。想更紧凑就直接把贴纸拖窄一点。
